# 摄像头模块集成说明

> **版本**: 2.1.0
> **更新日期**: 2026-08-03
> **适用范围**: 树莓派 5B + PCA9685 云台 + Picamera2 摄像头
> **服务器平台**: Windows 11 + Next.js
>
> **v2.1.0 变更**：新增第十四~十七章，补充服务端效果配置说明（设备类型注册、命令路由 API、前端控制卡片组件、执行器卡片路由）

---

## 一、概述

本文档说明摄像头颜色追踪模块如何规范化整合到系统中，作为一个特殊传感器设备打包上报。

### 1.1 核心能力

| 能力 | 说明 |
|------|------|
| 颜色追踪 | HSV 阈值检测 + 云台舵机自动跟随 |
| 实时视频流 | MJPEG 流，浏览器原生支持 |
| 帧抓取上传 | 定期上传 JPEG 帧到服务器，用于历史回放/AI 分析 |
| 规范化上报 | 摄像头作为 type=camera 的传感器节点，通过 `/api/device/report` 上报 |
| 接收控制参数 | 支持接收 pan/tilt 角度、追踪颜色参数 |

### 1.2 涉及的硬件

| 硬件 | 接口 | 地址/通道 | 说明 |
|------|------|-----------|------|
| Picamera2 | MIPI-CSI | - | 树莓派官方摄像头模块 |
| PCA9685 | I2C | 0x40 | 16 路 PWM 舵机驱动板 |
| 水平舵机 | PCA9685 | CH0 | Pan（左右旋转） |
| 俯仰舵机 | PCA9685 | CH1 | Tilt（上下俯仰） |

## 二、视频流上传方案选型

### 2.1 方案对比

| 方案 | 延迟 | 实现复杂度 | 兼容性 | 适用场景 |
|------|------|-----------|--------|---------|
| **MJPEG 流** | 100-300ms | 低 | 浏览器原生支持 | **实时预览（采用）** |
| RTMP 推流 | 1-3s | 高（需 RTMP 服务器） | 需播放器 | 直播场景 |
| WebRTC | <200ms | 极高（需信令服务器） | 现代浏览器 | 视频通话 |
| **帧抓取 HTTP 上传** | 取决于间隔 | 低 | RESTful API | **历史存储/AI 分析（采用）** |

### 2.2 采用方案：MJPEG 流 + 帧抓取 HTTP 上传混合

```
┌─────────────────────────────────────────────────────────────┐
│                      树莓派 5B                               │
│                                                             │
│  ┌─────────────┐    ┌──────────────┐    ┌───────────────┐  │
│  │ Picamera2   │───▶│ CameraTracker │───▶│ VideoStream   │  │
│  │ (摄像头)    │    │ (颜色追踪)    │    │ Server (8081) │  │
│  └─────────────┘    └──────┬───────┘    └───────┬───────┘  │
│                            │                    │          │
│                            ▼                    ▼          │
│                     ┌──────────────┐    ┌───────────────┐  │
│                     │ PanTilt      │    │ FrameUploader │  │
│                     │ Controller   │    │ (帧上传)      │  │
│                     └──────────────┘    └───────┬───────┘  │
└─────────────────────────────────────────────┼──┼───────────┘
                                               │  │
                          ┌────────────────────┘  │
                          ▼                       ▼
                   浏览器/Next.js 前端      Next.js 服务器
                   <img src="/stream">     POST /api/device/upload-image
                                          POST /api/device/report
```

**三层上传机制**：

| 层级 | 通道 | 用途 | 间隔 |
|------|------|------|------|
| 实时流 | MJPEG HTTP 流 | 浏览器实时预览 | 15 FPS |
| 帧抓取 | HTTP POST 上传 | 历史回放/AI 分析 | 30 秒（可配置） |
| 追踪数据 | HTTP POST 上报 | 服务器存储追踪结果 | 30 秒（随传感器上报） |

### 3.3 修改详情

#### services/video_stream_service.py（新增）

MJPEG 视频流服务，提供以下端点：

| 端点 | 方法 | Content-Type | 说明 |
|------|------|--------------|------|
| `/stream` | GET | multipart/x-mixed-replace | MJPEG 实时流，浏览器 `<img>` 标签可直接嵌入 |
| `/snapshot` | GET | image/jpeg | 当前帧 JPEG 快照 |
| `/status` | GET | application/json | 服务状态 JSON |
| `/` | GET | text/html | HTML 测试页面 |

**特性**：
- 多客户端并发支持（ThreadingMixIn）
- 50ms 帧缓存，避免高频请求时多次调用摄像头
- 帧抓取失败时返回最后一帧缓存，保证流连续性

## 四、摄像头节点上报格式

### 4.1 节点ID

```
CAM-1-001
│   │ └─ 序号
│   └─── 区域号
└─────── 设备类型前缀（CAM = Camera）
```

### 4.2 上报数据结构

摄像头作为 `type=camera` 的特殊传感器节点，通过 `POST /api/device/report` 上报：

```json
{
  "node_id": "CAM-1-001",
  "name": "颜色追踪摄像头",
  "type": "camera",
  "value": 1,
  "unit": "boolean",
  "location": "温室入口",
  "area": "温室1号区域",
  "feedback": {
    "power": true,
    "found": true,
    "resolution": [320, 240],
    "tracking_enabled": true,
    "is_running": true,
    "color_preset": "blue",
    "available_colors": ["blue", "red", "green", "yellow", "orange"],
    "pan_angle": 90.5,
    "tilt_angle": 88.2,
    "stream_url": "http://192.168.1.63:8081/stream",
    "snapshot_url": "http://192.168.1.63:8081/snapshot",
    "target_x": 160,
    "target_y": 120,
    "target_area": 1500.5,
    "error_pan": 0.5,
    "error_tilt": -2.3
  }
}
```

### 4.3 字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| node_id | string | 设备节点唯一标识 |
| name | string | 设备名称 |
| type | string | 设备类型（固定为 `camera`） |
| value | number | 1=检测到目标，0=未检测到 |
| unit | string | 单位（固定为 `boolean`） |
| location | string | 安装位置 |
| area | string | 区域名称 |
| feedback | object | 设备回馈数据 |

#### feedback 字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| power | boolean | 摄像头开关状态（on 命令=True，off 命令=False） |
| found | boolean | 是否检测到目标 |
| resolution | array | 摄像头分辨率 [width, height] |
| tracking_enabled | boolean | 是否启用自动追踪 |
| is_running | boolean | 追踪是否正在运行 |
| color_preset | string | 当前追踪颜色名称（color 命令切换后的实时值） |
| available_colors | array | 可用颜色预设列表（供服务端下拉选择） |
| pan_angle | number | 水平舵机当前角度（0-180） |
| tilt_angle | number | 俯仰舵机当前角度（0-180） |
| stream_url | string | MJPEG 实时流地址 |
| snapshot_url | string | 快照地址 |
| target_x | number | 目标中心 X 坐标（仅检测到时） |
| target_y | number | 目标中心 Y 坐标（仅检测到时） |
| target_area | number | 目标面积（像素²，仅检测到时） |
| error_pan | number | 水平偏差（像素，仅检测到时） |
| error_tilt | number | 垂直偏差（像素，仅检测到时） |

## 五、配置说明

### 5.1 settings.yaml 新增配置段

#### video_stream（MJPEG 视频流服务）

```yaml
# 视频流服务配置（MJPEG 实时流）
# 浏览器/Next.js 前端可直接通过 <img src="http://树莓派IP:8081/stream"> 嵌入实时视频
video_stream:
  enabled: true
  host: 0.0.0.0       # 监听地址（0.0.0.0 允许外部访问）
  port: 8081          # MJPEG 服务端口（避免与 WebSocket 8080 冲突）
  stream_fps: 15      # MJPEG 流帧率（帧/秒）
  jpeg_quality: 70    # JPEG 编码质量（1-100，越高质量越好但带宽占用越大）
```

#### frame_upload（帧上传配置）

```yaml
# 摄像头帧上传配置（定期上传 JPEG 帧到服务器）
# 用于历史回放、AI 分析、报警截图等场景
frame_upload:
  enabled: true
  interval: 30        # 帧上传间隔（秒）
  jpeg_quality: 75    # 上传帧 JPEG 质量（1-100）
  # 是否仅在检测到目标时上传（节省带宽和存储）
  # false=定时上传（用于历史回放）
  # true=仅检测到目标时上传（用于报警截图）
  upload_only_on_detection: false
```

#### device_mapping.camera（摄像头节点映射）

## 八、服务器端待办事项

### 8.1 新增 API 接口

服务器（Next.js on Win11）需新增以下接口：

| 接口 | 方法 | 说明 |
|------|------|------|
| `/api/device/upload-image` | POST | 接收摄像头帧上传，存储到 `public/uploads/camera/` |

### 8.2 接口实现建议

```javascript
// app/api/device/upload-image/route.js
import { writeFile, mkdir } from 'fs/promises';
import path from 'path';

export async function POST(request) {
  try {
    const formData = await request.formData();
    const nodeId = formData.get('node_id');
    const image = formData.get('image');
    const timestamp = formData.get('timestamp');
    const detection = formData.get('detection');

    // 生成文件名：CAM-1-001_20260803_143000.jpg
    const fileName = `${nodeId}_${timestamp.replace(/[- :]/g, '')}.jpg`;
    const uploadDir = path.join(process.cwd(), 'public', 'uploads', 'camera');
    const filePath = path.join(uploadDir, fileName);

    // 确保目录存在
    await mkdir(uploadDir, { recursive: true });

    // 写入文件
    const bytes = await image.arrayBuffer();
    await writeFile(filePath, Buffer.from(bytes));

    // TODO: 将元数据（node_id, timestamp, detection, file_path）写入数据库

    return Response.json({
      success: true,
      message: '图像上传成功',
      file_path: `/uploads/camera/${fileName}`,
      node_id: nodeId,
      timestamp: timestamp,
    });
  } catch (error) {
    return Response.json(
      { success: false, error: error.message },
      { status: 500 }
    );
  }
}
```

## 九、系统启动流程

摄像头模块随系统自动启动，流程如下：

```
System.start()
    │
    ├─▶ load_devices()              # 加载传感器和执行器
    ├─▶ initialize_devices()        # 初始化设备
    │
    ├─▶ _init_camera_and_tracking() # 初始化摄像头和云台
    │       │
    │       ├─▶ PanTiltController.initialize()  # 云台初始化
    │       ├─▶ CameraTracker.initialize()      # 摄像头初始化
    │       ├─▶ CameraTracker.start_tracking()  # 启动颜色追踪
    │       └─▶ _start_video_stream_service()   # 启动 MJPEG 流服务
    │
    ├─▶ _data_loop()                # 数据采集循环（含摄像头节点上报）
    │
    └─▶ _camera_frame_upload_loop() # 帧上传循环（独立线程）
```

## 十二、故障排查

### 12.1 视频流无法访问

1. 检查树莓派防火墙是否放行 8081 端口
2. 检查 `video_stream.enabled` 是否为 `true`
3. 访问 `http://树莓派IP:8081/status` 查看服务状态
4. 查看日志是否有视频流服务启动错误

### 12.2 帧上传失败

1. 检查服务器是否实现了 `/api/device/upload-image` 接口
2. 检查 `upload.server_url` 配置是否正确
3. 查看日志中 `[帧上传]` 相关错误信息
4. 检查网络连接是否正常

### 12.3 追踪不灵敏

1. 调整 `camera.tracking.gain`（增益系数，越小越灵敏）
2. 调整 `camera.tracking.dead_zone`（死区，越小越灵敏）
3. 调整 `camera.tracking.min_area`（最小检测面积，越小越灵敏）
4. 检查 HSV 阈值是否匹配目标颜色

### 12.4 云台不动

1. 检查 PCA9685 I2C 连接（地址 0x40）
2. 检查 `servo.enabled` 是否为 `true`
3. 检查舵机通道配置（pan_channel=0, tilt_channel=1）
4. 查看日志中云台初始化是否成功

## 十三、摄像头控制命令（服务端单独控制）

服务端可通过 WebSocket 或 HTTP 轮询向摄像头节点（CAM-1-001）发送控制命令，实现对摄像头的单独控制。

### 13.1 命令格式

与现有执行器命令格式一致：

```json
{
  "id": "命令ID",
  "actuator_id": "CAM-1-001",
  "command": "命令类型",
  "control_value": "控制值"
}
```

### 13.2 支持的命令

| command | control_value | 说明 |
|---------|---------------|------|
| `on` | null | 打开摄像头（启动追踪 + 视频流） |
| `off` | null | 关闭摄像头（停止追踪） |
| `value` | `{"pan":90,"tilt":90}` | 设置云台绝对角度 |
| `value` | `{"pan_delta":10,"tilt_delta":-5}` | 云台增量移动 |
| `value` | `"90,90"` | 字符串格式设置角度 |
| `track` | `"on"` / `"off"` | 开启/关闭自动跟踪 |
| `track` | `1` / `0` | 数字格式开关跟踪 |
| `track` | `true` / `false` | 布尔格式开关跟踪 |
| `color` | `"red"` / `"blue"` / `"green"` / `"yellow"` / `"orange"` | 切换追踪颜色 |
| `reset` | null | 云台复位到 90°,90° |

### 13.3 命令示例

#### 打开/关闭摄像头

```json
{ "id": "cmd_001", "actuator_id": "CAM-1-001", "command": "on" }
```
```json
{ "id": "cmd_002", "actuator_id": "CAM-1-001", "command": "off" }
```

#### 控制摄像头转动（设置绝对角度）

```json
{
  "id": "cmd_003",
  "actuator_id": "CAM-1-001",
  "command": "value",
  "control_value": { "pan": 45, "tilt": 90 }
}
```

#### 控制摄像头转动（增量移动）

```json
{
  "id": "cmd_004",
  "actuator_id": "CAM-1-001",
  "command": "value",
  "control_value": { "pan_delta": 10, "tilt_delta": -5 }
}
```

#### 单独控制跟踪开关

```json
{
  "id": "cmd_005",
  "actuator_id": "CAM-1-001",
  "command": "track",
  "control_value": "on"
}
```
```json
{
  "id": "cmd_006",
  "actuator_id": "CAM-1-001",
  "command": "track",
  "control_value": "off"
}
```

#### 切换追踪颜色

```json
{
  "id": "cmd_007",
  "actuator_id": "CAM-1-001",
  "command": "color",
  "control_value": "red"
}
```

#### 云台复位

```json
{ "id": "cmd_008", "actuator_id": "CAM-1-001", "command": "reset" }
```

### 13.4 命令回执

命令执行后，硬件端会通过 `/api/actuators/ack` 接口发送回执：

```json
{
  "actuator_id": "CAM-1-001",
  "command_id": "cmd_001",
  "status": "executed",
  "control_value": null,
  "state": "on"
}
```

| 字段 | 说明 |
|------|------|
| status | `executed`（成功）或 `failed`（失败） |
| state | `on`（摄像头运行中）或 `off`（摄像头已关闭） |

### 13.5 颜色预设

追踪颜色通过 `settings.yaml` 的 `camera.tracking.color_presets` 配置：

```yaml
camera:
  tracking:
    color_presets:
      blue:    # 蓝色（默认）
        hue_low: 96
        hue_up: 120
        ...
      red:     # 红色
        hue_low: 0
        hue_up: 10
        hue2_low: 170
        hue2_up: 180
        ...
      green:   # 绿色
        hue_low: 35
        hue_up: 85
        ...
      yellow:  # 黄色
        hue_low: 20
        hue_up: 35
        ...
      orange:  # 橙色
        hue_low: 10
        hue_up: 20
        ...
```

服务端发送 `color` 命令时，`control_value` 填写预设名称（如 `"red"`），硬件端会自动切换到对应的 HSV 阈值。

### 13.6 命令执行流程

```
服务端
  │
  ├─▶ WebSocket 推送命令 ─────┐
  │  或 HTTP 轮询获取命令      │
  │                            ▼
  │                    ┌───────────────┐
  │                    │ system.py     │
  │                    │ _execute_     │
  │                    │ single_command│
  │                    └───────┬───────┘
  │                            │
  │                    actuator_id == CAM-1-001?
  │                            │ 是
  │                            ▼
  │                    ┌───────────────┐
  │                    │ _handle_      │
  │                    │ camera_command│
  │                    └───────┬───────┘
  │                            │
  │              ┌─────────────┼─────────────┐
  │              ▼             ▼             ▼
  │        on/off/value    track        color/reset
  │        云台控制        跟踪开关      颜色切换/复位
  │                            │
  │                            ▼
  │◀───── 发送命令回执 ────────┘
  │       /api/actuators/ack
```

### 13.7 服务器端 API 调用示例（Next.js）

#### 发送命令（HTTP 方式）

```javascript
// 发送摄像头转动命令
async function moveCamera(pan, tilt) {
  const response = await fetch('/api/actuators/CAM-1-001/commands', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      command: 'value',
      control_value: { pan, tilt },
    }),
  });
  return response.json();
}

// 开启/关闭跟踪
async function setTracking(enable) {
  const response = await fetch('/api/actuators/CAM-1-001/commands', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      command: 'track',
      control_value: enable ? 'on' : 'off',
    }),
  });
  return response.json();
}

// 切换追踪颜色
async function setTrackColor(color) {
  const response = await fetch('/api/actuators/CAM-1-001/commands', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      command: 'color',
      control_value: color,
    }),
  });
  return response.json();
}
```

#### 发送命令（WebSocket 方式）

```javascript
// 通过 WebSocket 发送命令
function sendCameraCommand(ws, command, controlValue = null) {
  ws.send(JSON.stringify({
    actuator_id: 'CAM-1-001',
    command: command,
    control_value: controlValue,
  }));
}

// 使用示例
sendCameraCommand(ws, 'on');                          // 打开摄像头
sendCameraCommand(ws, 'value', { pan: 45, tilt: 90 }); // 转动到45°,90°
sendCameraCommand(ws, 'track', 'off');                 // 关闭跟踪
sendCameraCommand(ws, 'color', 'red');                 // 切换到红色追踪
sendCameraCommand(ws, 'reset');                        // 云台复位
```

## 十六、命令路由 API（app/api/actuators/[id]/commands/route.ts）

### 16.1 camera 命令处理分支

POST 接口在 `switch (controlType)` 中新增 `camera` 分支，处理六种命令：

| 命令 | 必填字段 | control_value 存储 | command_data 存储 |
|------|----------|---------------------|---------------------|
| `on` | 无 | null | `{type:'on'}` |
| `off` | 无 | null | `{type:'off'}` |
| `reset` | 无 | null | `{type:'reset'}` |
| `value` | `pan`+`tilt` 或 `pan_delta`+`tilt_delta` 或 `value` | pan 角度或 pan_delta | `{type:'value', pan, tilt}` 或 `{type:'value', pan_delta, tilt_delta}` 或 `{type:'value', value}` |
| `track` | `value`（on/off/true/false/1/0） | 1 或 0 | `{type:'track', value}` |
| `color` | `value` 或 `color`（颜色名称） | null | `{type:'color', color}` |

### 16.2 命令校验规则

| 校验项 | 规则 |
|--------|------|
| command 字段 | 必填，必须是 on/off/value/track/color/reset 之一 |
| value 命令的 pan/tilt | 范围 0-180（自动 clamp） |
| color 命令 | 颜色名称必须是 red/blue/green/yellow/orange 之一 |
| track 命令 | value 支持 'on'/'off'/true/false/1/0 多种格式 |

### 16.3 WebSocket 转发扩展字段

命令插入数据库后，通过 `sendCommandToActuator()` 经 WebSocket 实时推送到硬件端。摄像头命令会附加以下扩展字段（供硬件端 `_execute_single_command` 解析）：

```typescript
// 基础字段（所有命令共有）
{
  id: commandId,
  actuator_id: 'CAM-1-001',
  command: 'value',           // 命令类型
  control_value: 90,          // 主控制值
  control_type: 'camera',
  status: 'pending',
  created_at: '2026-08-03T...'
}

// 摄像头扩展字段
commandData.camera_command = 'value'   // 命令子类型

// value 命令的参数（三选一）
commandData.pan = 90; commandData.tilt = 90              // 绝对角度
commandData.pan_delta = 10; commandData.tilt_delta = -5   // 增量移动
commandData.value = "90,90"                               // 字符串格式

// track 命令的参数
commandData.value = 'on'    // 或 'off'/true/false/1/0

// color 命令的参数
commandData.color = 'red'   // 颜色名称
```

### 16.4 回执处理

硬件端执行命令后通过 PATCH 接口发送回执，服务端处理逻辑：

| 回执状态 | 服务端动作 |
|----------|------------|
| `executed` + command=on/off | 更新 `actuators.state` 为 on/off |
| `executed` + command=value + control_value | 更新 `actuators.state`（>0 为 on）和 `control_value` |
| `executed` + command=track/color/reset | 仅更新 `executed_at`，不改变 state（由下次 feedback 上报反映） |
| `failed` | 仅记录失败状态，不更新执行器状态 |
| 任意回执 | 解锁执行器（`locked = 0`） |

> **幂等支持**：如果命令已是目标状态（如 WebSocket 和 HTTP 双通道回执竞态），PATCH 接口直接返回成功，不重复更新。

### 17.4 交互效果说明

#### 视频流显示
- 摄像头开启且 `stream_url` 存在时，通过 `<img>` 标签直接嵌入 MJPEG 流
- 加载中显示半透明黑色遮罩 + 旋转图标 + "视频加载中..."文案
- 加载失败显示橙色警告图标 + "视频流加载失败" + 重试按钮
- 摄像头关闭时显示灰色 `VideoOff` 图标 + "摄像头未开启"
- 右上角提供重新加载按钮（强制刷新 `img` 的 `key` 属性）

#### 云台控制
- **方向十字按钮**：上/下/左/右四个方向，每次点击发送 `pan_delta`/`tilt_delta` 为 ±10° 的增量命令；中心按钮为复位
- **Pan/Tilt 滑块**：范围 0-180°，步进 1°，拖动时本地状态实时更新，点击"应用角度"按钮才发送命令
- **应用角度按钮**：当滑块值与当前实际角度相同时禁用（避免冗余命令）
- **复位按钮**：发送 `reset` 命令，同时将本地滑块重置为 90°

#### 追踪颜色选择
- 5 个颜色按钮：红色 `#ef4444`、蓝色 `#3b82f6`、绿色 `#22c55e`、黄色 `#eab308`、橙色 `#f97316`
- 每个按钮显示对应颜色的圆点 + 中文标签
- 当前选中颜色（`color_preset` 匹配）高亮为主题色背景
- 未开启追踪时颜色按钮禁用（`opacity-50 cursor-not-allowed`）
- 点击按钮发送 `color` 命令，`control_value` 为颜色英文名

#### 状态反馈
- 命令发送后底部显示状态提示条（5 种状态，不同颜色和图标）
- `sending`：蓝色背景，旋转图标，"正在发送指令..."
- `pending`：黄色背景，时钟图标，"等待硬件回执 (30秒)"
- `executed`：绿色背景，对勾图标，"指令执行成功"
- `failed`：红色背景，叉号图标，"指令执行失败"
- `timeout`：橙色背景，警告图标，"控制超时，请重试"

### 17.5 禁用状态规则

以下任一条件成立时，所有控制元素禁用：

| 条件 | 判断逻辑 |
|------|----------|
| 执行器离线 | `actuator.status !== 'online'` |
| 命令发送中 | `commandStatus === 'sending' \|\| 'pending'` |
| 执行器锁定 | `actuator.locked === 1`（有命令正在执行） |
| 摄像头关闭时操作追踪/颜色 | `actuator.state !== 'on'` |

```typescript
// 摄像头识别逻辑：类型为 camera 时使用摄像头控制卡片
const isCamera = actuator.type === 'camera'

if (isCamera) {
  return (
    <CameraControlCard
      actuator={actuator}
      onControl={(cmd) => onControl(cmd)}
      commandStatus={commandStatus}
      timeout={timeout}
    />
  )
}
```

### 18.3 命令类型联合

## 十九、端到端数据流总结

### 19.1 命令下发流程（服务端 → 硬件端）

```
用户操作 CameraControlCard
    │
    ├─ onControl({control_type:'camera', command:'value', pan:90, tilt:90})
    │
    ▼
POST /api/actuators/CAM-1-001/commands
    │
    ├─ control_type === 'camera' 分支处理
    ├─ 校验命令和参数
    ├─ INSERT actuator_commands (command='value', control_value=90, command_data={type:'value',pan:90,tilt:90})
    ├─ UPDATE actuators SET locked=1
    │
    ├─ sendCommandToActuator() WebSocket 推送
    │   └─ commandData = {id, actuator_id, command, control_value, control_type:'camera',
    │                     camera_command:'value', pan:90, tilt:90, status:'pending'}
    │
    ▼
硬件端 system.py._execute_single_command()
    │
    ├─ actuator_id == 'CAM-1-001' → _handle_camera_command('value', {pan:90,tilt:90})
    ├─ _handle_camera_move() → _pan_tilt.set_position(90, 90)
    │
    ├─ _send_command_ack_fast() 回执
    │   ├─ WebSocket send_command_ack()
    │   └─ HTTP PATCH /api/actuators/CAM-1-001/commands
    │
    ▼
服务端 PATCH 接口
    ├─ UPDATE actuator_commands SET status='executed'
    ├─ UPDATE actuators SET state='on', locked=0
    └─ 前端轮询获知 executed 状态，更新 UI
```

### 19.2 状态上报流程（硬件端 → 服务端 → 前端）

```
硬件端 system.py._collect_and_upload()（每 30 秒）
    │
    ├─ _build_camera_node()
    │   └─ feedback = {power, found, resolution, tracking_enabled, is_running,
    │                  color_preset, available_colors, pan_angle, tilt_angle,
    │                  stream_url, snapshot_url, target_x/y/area, error_pan/tilt}
    │
    ▼
POST /api/device/report
    │
    ├─ 服务端存储到 device_readings 表
    ├─ 更新 actuators 表的 feedback 字段
    │
    ▼
前端轮询 /api/devices 或 WebSocket 推送
    │
    ├─ ActuatorCard 识别 type==='camera'
    ├─ 渲染 CameraControlCard
    └─ feedback 字段驱动视频流地址、滑块角度、颜色高亮、检测徽章等 UI
```

### 19.3 视频流独立通道

```
硬件端 VideoStreamService (8081 端口)
    │
    ├─ GET /stream → multipart/x-mixed-replace MJPEG 流
    │
    ▼
浏览器 <img src="http://树莓派IP:8081/stream">
    │
    └─ CameraControlCard 视频流显示区直接渲染
        （不经过服务端，浏览器直连树莓派 8081 端口）
```

> **注意**：视频流不经过 Next.js 服务端中转，浏览器直接连接树莓派 8081 端口，降低服务端负载和延迟。服务端仅负责命令下发和状态上报，不参与视频流传输。
