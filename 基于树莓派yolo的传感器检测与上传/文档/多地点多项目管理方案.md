# 智慧农业物联网平台 - 多地点多项目管理方案

## 更新日期：2026-08-03

---

## 1. 业务场景分析

### 1.1 典型用户场景

| 场景 | 描述 | 设备规模 | 摄像头规模 |
|------|------|---------|---------|
| **家庭农场** | 单一地点，种植1-2种作物 | 5-20个设备 | 1-2 个摄像头节点 |
| **合作社** | 多个农户，各自管理 | 50-200个设备 | 每农户 1 个摄像头节点 |
| **农业企业** | 多个基地，统一管理 | 500-5000个设备 | 每基地 2-4 个摄像头节点 |
| **农业园区** | 多功能区（种植/养殖/加工） | 1000-10000个设备 | 每功能区 2-6 个摄像头节点 |

### 1.2 核心需求

1. **层级管理**：基地 → 大棚/地块 → 区域 → 设备
2. **数据隔离**：不同基地数据相互独立
3. **权限控制**：管理员/技术员/工人 分级权限
4. **批量操作**：跨基地数据对比、批量控制
5. **资源复用**：设备模板、传感器配置、控制策略
6. **摄像头多地点接入（v2.2.0 新增）**：多树莓派多摄像头支持，每地点独立配置摄像头节点 ID、视频流端口、颜色预设

## 2. 数据架构设计

### 2.1 实体关系模型

```
农场/基地 (Farm)
├── 区域 (Zone)
│   ├── 大棚/地块 (Greenhouse/Field)
│   │   ├── 传感器 (Sensor)
│   │   ├── 执行器 (Actuator)
│   │   └── 监控点 (Monitor)
│   └── 设备分组 (DeviceGroup)
├── 作物批次 (CropBatch)
│   ├── 种植计划
│   └── 生长周期
└── 用户权限 (UserPermission)
```

### 2.2 数据库表设计

```sql
-- 1. 农场/基地表
CREATE TABLE farms (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL,
    code TEXT UNIQUE NOT NULL,        -- 基地编码（如：BJ-001）
    address TEXT,
    latitude REAL,
    longitude REAL,
    area REAL,                         -- 面积（亩）
    farm_type TEXT,                    -- 类型：greenhouse/field/mixed
    owner_id INTEGER,                  -- 负责人
    status TEXT DEFAULT 'active',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 2. 区域表
CREATE TABLE zones (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    farm_id INTEGER NOT NULL,
    name TEXT NOT NULL,
    code TEXT NOT NULL,
    zone_type TEXT,                    -- 类型：greenhouse/field/warehouse
    area REAL,
    description TEXT,
    status TEXT DEFAULT 'active',
    FOREIGN KEY (farm_id) REFERENCES farms(id),
    UNIQUE(farm_id, code)
);

-- 3. 监控点表（大棚/地块内的具体位置）
CREATE TABLE monitor_points (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    zone_id INTEGER NOT NULL,
    name TEXT NOT NULL,
    code TEXT NOT NULL,
    point_type TEXT,                   -- 类型：raised_bed/soil_point/air_point
    position_x REAL,                   -- 坐标位置
    position_y REAL,
    description TEXT,
    FOREIGN KEY (zone_id) REFERENCES zones(id),
    UNIQUE(zone_id, code)
);

-- 4. 设备分组表
CREATE TABLE device_groups (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    farm_id INTEGER NOT NULL,
    name TEXT NOT NULL,
    group_type TEXT,                   -- 类型：sensor/actuator/mixed
    description TEXT,
    FOREIGN KEY (farm_id) REFERENCES farms(id)
);

-- 5. 扩展传感器表（添加基地关联）
ALTER TABLE sensors ADD COLUMN farm_id INTEGER;
ALTER TABLE sensors ADD COLUMN zone_id INTEGER;
ALTER TABLE sensors ADD COLUMN monitor_point_id INTEGER;
ALTER TABLE sensors ADD COLUMN device_group_id INTEGER;

-- 6. 扩展执行器表（添加基地关联）
ALTER TABLE actuators ADD COLUMN farm_id INTEGER;
ALTER TABLE actuators ADD COLUMN zone_id INTEGER;
ALTER TABLE actuators ADD COLUMN device_group_id INTEGER;

-- 7. 作物批次表
CREATE TABLE crop_batches (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    farm_id INTEGER NOT NULL,
    zone_id INTEGER NOT NULL,
    crop_type TEXT NOT NULL,           -- 作物类型
    variety TEXT,                      -- 品种
    batch_code TEXT UNIQUE NOT NULL,   -- 批次编码
    planting_date DATE,
    expected_harvest_date DATE,
    actual_harvest_date DATE,
    area REAL,                         -- 种植面积
    status TEXT DEFAULT 'growing',     -- 状态：planted/growing/harvested
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (farm_id) REFERENCES farms(id),
    FOREIGN KEY (zone_id) REFERENCES zones(id)
);

-- 8. 用户权限表
CREATE TABLE user_permissions (
    id INTEGER PRIMARY KEY SUPERKEY AUTOINCREMENT,
    user_id INTEGER NOT NULL,
    farm_id INTEGER NOT NULL,
    role TEXT NOT NULL,                -- 角色：owner/admin/technician/worker
    permissions TEXT,                  -- JSON格式的权限列表
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (farm_id) REFERENCES farms(id),
    UNIQUE(user_id, farm_id)
);

-- 9. 设备模板表（用于快速创建设备）
CREATE TABLE device_templates (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL,
    device_type TEXT NOT NULL,         -- sensor/actuator
    device_model TEXT,                 -- 型号
    default_config TEXT,               -- JSON格式的默认配置
    description TEXT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 10. 控制策略表（跨基地复用）
CREATE TABLE control_strategies (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL,
    strategy_type TEXT,                -- 类型：irrigation/ventilation/lighting
    config TEXT NOT NULL,              -- JSON格式的策略配置
    is_template INTEGER DEFAULT 0,     -- 是否为模板
    created_by INTEGER,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

## 6. 技术要点

### 6.1 数据隔离方案
- 每个API请求携带 `farm_id` 参数
- 数据库查询自动添加 `WHERE farm_id = ?` 条件
- 使用中间件统一处理权限校验

### 6.2 设备编号规则
```
[基地编码]-[区域编码]-[设备类型]-[序号]
示例：BJ-001-GH1-S-001（北京001号基地-1号大棚-传感器-001）

摄像头节点编号（沿用 CAM-{gatewayId}-{nodeId} 格式，与基地/区域编码建立映射关系）：
示例：CAM-1-001（1号网关-001号摄像头节点，归属 BJ-001-GH1 区域）
     CAM-2-001（2号网关-001号摄像头节点，归属 SH-002-GH2 区域）
```

### 6.3 缓存策略
- 基地配置信息：Redis缓存，5分钟过期
- 设备列表：Redis缓存，1分钟过期
- 实时数据：不缓存，直接查询

### 6.4 性能优化
- 设备列表分页加载
- 区域树形结构懒加载
- 数据聚合使用数据库视图
- 历史数据按时间分表
- 摄像头视频流端口按地点/树莓派规划，避免端口冲突（详见 7.3 节）

## 7. 摄像头多地点配置（v2.2.0 新增）

### 7.1 多树莓派多摄像头架构

```
服务端（Next.js 3000 端口）
        ▲
        │  /api/device/report         /api/actuators/CAM-x-xxx/commands
        │  /api/device/upload-image   PATCH /api/actuators/CAM-x-xxx/commands
        │
        │  WebSocket 8080 端口
        │
┌───────┴────────┬─────────────────┬─────────────────┐
│  树莓派 #1     │  树莓派 #2      │  树莓派 #N      │
│  北京 001 基地  │  上海 002 基地   │  广州 003 基地   │
│  8081 端口      │  8081 端口       │  8081 端口       │
│  CAM-1-001     │  CAM-2-001      │  CAM-3-001      │
│  CAM-1-002     │  CAM-2-002      │  CAM-3-002      │
│  (Picamera2 +  │  (Picamera2 +   │  (Picamera2 +   │
│   PCA9685 云台) │   PCA9685 云台) │   PCA9685 云台) │
└────────────────┴─────────────────┴─────────────────┘
        │                  │                 │
        ▼                  ▼                 ▼
  浏览器直连 8081     浏览器直连 8081    浏览器直连 8081
  （MJPEG 流）        （MJPEG 流）       （MJPEG 流）
```

**架构要点**：
- 每个树莓派独立运行 OpenCV + MJPEG 流服务，本地 8081 端口
- 浏览器通过 `stream_url` 直连对应树莓派，视频流不经过服务端中转
- 服务端只负责节点注册、命令下发、回执处理、帧上传接收
- 多地点树莓派通过 `gateway_ip` 区分，同网关下多摄像头通过 `nodeId` 区分

### 7.2 settings.yaml 配置（device_mapping.camera）

每个树莓派本地 `settings.yaml` 独立配置摄像头节点，服务端通过 `/api/device/report` 自动注册。

```yaml
# settings.yaml —— 摄像头多地点配置示例
# 文件位置：树莓派本地（/home/pi/sensor-system/config/settings.yaml）

# 基地/区域归属信息（用于上报时关联到 farms/zones 表）
farm:
  code: "BJ-001"              # 基地编码，对应 farms.code
  name: "北京001号基地"
  zone_code: "GH1"            # 区域编码，对应 zones.code

# 网关信息
gateway:
  ip: "192.168.1.101"         # 本树莓派 IP（gateway_ip）
  name: "raspberry-pi-bj-001"

# 摄像头节点配置（多摄像头节点列表）
camera:
  # 节点 ID（CAM-{gatewayId}-{nodeId}，gatewayId 由服务端根据 gateway.ip 自动分配）
  node_id: "001"
  type: "camera"
  control_type: "string"

  # 视频流服务（树莓派本地 OpenCV MJPEG 流）
  stream:
    host: "0.0.0.0"
    port: 8081               # 本地视频流端口（每树莓派默认 8081，浏览器按 stream_url 直连）
    path: "/stream"          # MJPEG 流路径
    snapshot_path: "/snapshot"
    status_path: "/status"
    resolution: "640x480"
    fps: 20

  # PCA9685 云台舵机驱动（I2C 0x40）
  ptz:
    i2c_address: 0x40
    pan_channel: 0           # CH0 = Pan
    tilt_channel: 1          # CH1 = Tilt
    pan_min: 0
    pan_max: 180
    pan_center: 90
    tilt_min: 0
    tilt_max: 90
    tilt_center: 45

  # 颜色追踪（OpenCV HSV 检测 + PID 控制）
  tracking:
    enabled: false           # 默认关闭，由前端 track on/off 控制
    default_color: "blue"
    pid:
      kp: 0.15
      ki: 0.0
      kd: 0.05
    # 颜色预设 HSV 阈值（每地点可独立调整，适应光照差异）
    color_presets:
      blue:    { lower: [100, 100, 100], upper: [130, 255, 255] }
      red:     { lower: [0, 100, 100],   upper: [10, 255, 255] }
      green:   { lower: [40, 100, 100],  upper: [80, 255, 255] }
      yellow:  { lower: [20, 100, 100],  upper: [35, 255, 255] }
      orange:  { lower: [10, 100, 100],  upper: [25, 255, 255] }

  # 帧上传（POST /api/device/upload-image）
  upload:
    enabled: true
    interval: 30             # 上传间隔（秒）
    quality: 80              # JPEG 质量
    server_url: "http://192.168.1.100:3000/api/device/upload-image"

# 设备映射（device_mapping）——多摄像头节点扩展示例
device_mapping:
  camera:
    # 节点 1：本树莓派主摄像头（与上面 camera 节配置一致）
    - node_id: "001"
      stream_port: 8081
      ptz_i2c_address: 0x40
      default_color_preset: "blue"
    # 节点 2：本树莓派扩展摄像头（USB 摄像头，可挂多个）
    - node_id: "002"
      stream_port: 8082      # 第二个摄像头使用 8082 端口避免冲突
      ptz_i2c_address: 0x41  # 第二块 PCA9685 板（I2C 地址改为 0x41）
      default_color_preset: "red"
```

### 7.3 视频流端口规划

| 基地 | 树莓派 IP | 摄像头节点 | 视频流端口 | stream_url |
|------|----------|-----------|-----------|-----------|
| BJ-001 | 192.168.1.101 | CAM-1-001 | 8081 | http://192.168.1.101:8081/stream |
| BJ-001 | 192.168.1.101 | CAM-1-002 | 8082 | http://192.168.1.101:8082/stream |
| SH-002 | 192.168.1.201 | CAM-2-001 | 8081 | http://192.168.1.201:8081/stream |
| SH-002 | 192.168.1.201 | CAM-2-002 | 8082 | http://192.168.1.201:8082/stream |
| GZ-003 | 192.168.1.301 | CAM-3-001 | 8081 | http://192.168.1.301:8081/stream |

**端口规划规则**：
- 同一树莓派上多个摄像头：8081、8082、8083... 递增
- 不同树莓派之间端口互不冲突（IP 不同）
- 服务端 3000 端口、WebSocket 8080 端口、数据库端口需与视频流端口隔离
- `stream_url` 字段由树莓派上报时自动填充，前端按 `stream_url` 直连

### 7.4 每地点独立配置项

每个树莓派/地点的 `settings.yaml` 可独立配置以下摄像头参数：

| 配置项 | 说明 | 示例 |
|--------|------|------|
| `camera.node_id` | 摄像头节点 ID（与 gatewayId 组成 CAM-x-xxx） | "001" |
| `camera.stream.port` | 本地视频流端口 | 8081 |
| `camera.ptz.i2c_address` | PCA9685 I2C 地址（多板时需改地址） | 0x40 |
| `camera.ptz.pan_center` | Pan 中位角度（机械安装差异） | 90 |
| `camera.ptz.tilt_center` | Tilt 中位角度 | 45 |
| `camera.tracking.default_color` | 默认颜色预设 | "blue" |
| `camera.tracking.color_presets` | HSV 阈值（适应本地光照） | blue/red/green/yellow/orange |
| `camera.tracking.pid` | PID 控制参数（适应不同舵机负载） | kp=0.15 |
| `camera.upload.interval` | 帧上传间隔（秒） | 30 |
| `camera.upload.quality` | JPEG 压缩质量 | 80 |
| `farm.code` / `farm.zone_code` | 基地/区域归属（关联 farms/zones 表） | "BJ-001" / "GH1" |

### 7.5 多地点摄像头控制流程

```
1. 用户在 /dashboard 切换基地（如 BJ-001）
2. 设备管理页通过 GET /api/devices?farm_id=BJ-001&type=camera 获取该基地摄像头列表
3. 前端渲染 camera-card，stream_url 指向对应树莓派 IP:8081/stream
4. 浏览器直连树莓派 MJPEG 流，服务端不参与视频流转发
5. 用户点击云台/颜色追踪按钮 → POST /api/actuators/CAM-1-001/commands
6. 服务端通过 WebSocket（按 gateway_ip 推送）下发命令到对应树莓派
7. 树莓派执行后通过 PATCH /api/actuators/CAM-1-001/commands 回执
8. 服务端更新 feedback 字段，前端 WebSocket 推送状态更新
9. 树莓派定时上传帧到 /api/device/upload-image（携带 farm_id/area）
10. 服务端按 farm_id 归档帧图片，可在基地详情页查看历史回放
```

### 7.6 多地点摄像头数据隔离

- **节点隔离**：每个摄像头节点（CAM-x-xxx）独立上报，feedback 字段互不干扰
- **帧上传隔离**：`/api/device/upload-image` 必须携带 `farm_id` 和 `area`，按基地归档存储
- **命令隔离**：`/api/actuators/CAM-x-xxx/commands` 按 actuator_id 隔离，仅目标树莓派接收
- **视频流隔离**：`stream_url` 按 IP+端口 区分，浏览器只直连用户选中的摄像头
- **权限隔离**：用户只能看到自己 `user_permissions` 中授权的 `farm_id` 下的摄像头节点
