# MiMoCode 可直接使用的规则总结

基于 .trae 技能文件提取的规则，可直接用于指导工作。

## 一、农业物联网嵌入式开发规则

### 1. 工程架构规范
- 分层设计：硬件驱动层→协议接口层→应用业务层
- 严格区分驱动与业务逻辑，禁止将业务代码嵌入驱动程序
- 统一命名规则、注释标准及错误码定义

### 2. 时钟与资源初始化
- 遵循正确的初始化顺序：系统时钟→GPIO/外设时钟使能→中断分组→驱动初始化→开启总中断
- 快速排查初始化顺序错误导致的故障

### 3. 低功耗设计（农业物联网核心）
- 单片机低功耗模式（STOP/STANDBY）配置
- 传感器分时供电设计，非采集时段切断电源
- 外设时钟与GPIO优化，关闭无用外设时钟
- 通信模块休眠/断电控制
- 定时器/中断替代死等延时

### 4. 传感器数据处理
- 数据滤波算法（多次采样平均、中值滤波）
- 异常值处理，通过上下限阈值判断剔除无效数据
- 数据单位统一、精度对齐
- 传感器温漂补偿、零点校准

### 5. 通信可靠性保障
- 数据包格式设计，添加帧头、帧尾、长度字段及CRC8/CRC16校验和
- 通信超时重传机制
- 心跳包保活机制
- 数据缓存能力，应对网络抖动
- 处理NB-IoT/4G模块通信异常

### 6. 控制逻辑安全设计
- 输出互锁逻辑，防止设备错误联动
- 设备超时保护机制
- Flash/EEPROM数据存储，实现掉电保护
- 手动/自动模式切换功能
- 过流、过载检测能力

### 7. 中断与资源竞争处理
- 中断服务函数优化，确保函数简洁
- volatile关键字使用，共享变量修饰
- 避免在中断服务函数中执行耗时操作
- 合理配置中断优先级

### 8. 内存与堆栈管理
- 规范内存使用，防止栈溢出
- 避免使用动态内存（malloc）
- 固定缓冲区设计，做好边界检查
- 配置看门狗，实现设备自动复位

### 9. 日志与调试
- 日志打印规范，仅打印关键节点状态码
- 熟练使用SWD/JTAG在线调试工具
- 异常信息自动记录功能

### 10. 代码可维护与可扩展性
- 可配置驱动程序，便于快速替换传感器、通信模块
- 业务参数远程配置功能
- 预留OTA升级接口
- 遵循高内聚、低耦合原则设计代码

## 二、Keil编译结果检测规则

### 1. 路径自动检测
- 首先检查是否存在上次成功编译的路径记录
- 检查当前目录是否存在*.uvprojx文件
- UV4.exe路径检测：D:\Program Files\UV4\UV4.exe 或 D:\Program Files (x86)\UV4\UV4.exe

### 2. 执行编译命令
```powershell
& "[自动检测的UV4路径]" -b "[自动检测的项目文件路径]"
```

### 3. 日志关键检测
- 错误：匹配 \d+ Error(s) → 错误数量
- 警告：匹配 \d+ Warning(s) → 警告数量
- 结果：Target created（成功）/ Target not created（失败）
- 文件：检查Objects/*.axf、*.hex是否存在

### 4. 结果判定
- ✅ 完全成功：0错误 + 0警告 + Target created + 文件存在
- ⚠️ 带警告成功：0错误 + 有警告 + Target created + 文件存在
- ❌ 编译失败：≥1错误 或 Target not created

### 5. 警告修复
- 函数隐式声明：添加函数原型声明
- 文件末尾缺少换行：添加换行符

### 6. 路径记录与更新
- 编译成功后记录当前使用的路径到配置文件
- 编译失败时尝试其他可能的路径组合

## 三、Keil固件烧录规则

### 1. 前置检查
- 确认固件已成功编译（调用keil-compile-result-check）
- 检查Objects目录下是否存在.hex/.axf/.bin文件

### 2. 固件文件检测
- 查找项目Objects目录下最新的.hex/.axf/.bin文件
- 优先使用.hex文件（兼容性最好）

### 3. 串口/调试器检测
- 使用embedded-agent-bridge的eabctl自动检测可用串口
- 支持ST-Link、J-Link、CMSIS-DAP等调试器

### 4. 芯片类型检测
- 从Keil项目文件中解析目标芯片型号
- 或通过调试器读取芯片ID自动识别

### 5. 烧录命令
```powershell
# 启动serial daemon
eabctl --device [设备名称] start --port auto

# 烧录固件（STM32示例）
eabctl --device [设备名称] flash [固件文件] --chip stm32
```

### 6. 结果验证
- 检查烧录命令的退出码
- 读取串口输出确认芯片启动正常
- 使用eabctl status检查连接健康状态

## 四、临时文件管理规则

### 1. 文件命名规范
```
[前缀]_[创建日期]_[描述]_[创建者]_[版本/序号].[扩展名]
```

### 2. 文件头注释
```python
# ============================================================
# 临时测试文件声明
# ============================================================
# 文件用途: [简要描述文件用途]
# 创建日期: [YYYY-MM-DD]
# 创建者:   [创建者姓名]
# 预期到期: [YYYY-MM-DD]
# 关联任务: [关联的任务或 Issue ID，可选]
# 自动清理: [true/false]（默认 true，测试完成后自动清理）
# ============================================================
```

### 3. 存储路径
- `temp/test_scripts/` - 临时测试脚本
- `temp/test_data/` - 临时测试数据
- `temp/test_output/` - 临时测试输出
- `temp/debug/` - 调试临时文件

### 4. 自动清理机制
- **触发条件**：测试脚本执行完成且退出码为0，用户确认测试效果符合预期
- **静默清理**：默认情况下，测试成功后自动清理，无需用户确认
- **用户确认**：如果测试文件较大（>10MB）或包含重要数据，会提示用户确认后再清理

### 5. 保留期限管理

| 临时文件类型 | 测试阶段 | 基础保留期限 | 最长期限 |
|------------|---------|------------|---------|
| 快速验证脚本（单次算法验证） | 单元测试 | 1天 | 3天 |
| 快速验证脚本（功能验证） | 集成测试 | 3天 | 7天 |
| 测试数据文件（核心场景） | 系统测试/验收测试 | 14天 | 21天 |
| 测试数据文件（普通场景） | 单元/集成测试 | 7天 | 14天 |
| 调试输出文件（线上问题排查） | 生产调试 | 7天 | 14天 |
| 调试输出文件（普通调试） | 开发调试 | 3天 | 7天 |
| 临时备份文件（核心版本） | 版本发布前 | 14天 | 21天 |
| 临时备份文件（普通版本） | 日常开发 | 7天 | 14天 |
| 其他临时文件（关联里程碑） | 里程碑测试 | 15天 | 30天 |
| 其他临时文件（一般场景） | 常规测试 | 7天 | 30天 |

### 6. 动态延期规则

| 文件价值等级 | 延期次数 | 单次最长延期 | 累计最长延期 |
|------------|---------|------------|------------|
| 低价值（单次验证） | 0次 | - | - |
| 中价值（常规测试） | 1次 | 7天 | 7天 |
| 高价值（核心测试/问题排查） | 2次 | 10天 | 20天 |

### 7. 清理机制
- **每日清理**：清理已过期的临时文件
- **每周清理**：提醒即将到期的临时文件
- **月度清理**：全面检查所有临时文件
- **磁盘使用率 > 85%**：优先清理低价值、超期未处理的临时文件
- **磁盘使用率 > 90%**：清理所有超期文件，包括部分中价值文件

### 8. 归档机制
- **短期归档**：30天，适用于常规测试复盘
- **长期归档**：90天，适用于核心问题排查、客户验收相关
- **特殊保留**：最长180天，需双审批

### 9. 核心原则
- **最小必要原则**：保留期限 =「完成测试/复盘所需的最短时间 + 3天缓冲」
- **分级管控原则**：按文件价值、测试阶段差异化设定期限
- **自动化 + 人工结合**：基础清理自动化，高价值文件人工评估
- **动态优化原则**：基于实际使用数据持续调整

## 五、通用工作规则

### 1. 编译检查规则
- 编译前检查项目文件和编译工具路径
- 编译后检查错误数、警告数、目标文件生成情况
- 自动记录成功路径，优化下次编译效率

### 2. 烧录检查规则
- 烧录前确认固件已成功编译
- 自动检测串口和调试器
- 烧录后验证芯片启动状态

### 3. 临时文件管理规则
- 严格遵循命名规范
- 自动清理已完成测试的临时文件
- 定期归档有价值的临时文件

### 4. 代码质量规则
- 遵循分层架构设计
- 注重低功耗优化（农业物联网）
- 保障通信可靠性
- 确保控制逻辑安全
